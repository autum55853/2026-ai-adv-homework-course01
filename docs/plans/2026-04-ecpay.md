# 串接綠界（ECPay）信用卡金流

**日期**：2026-04-13
**狀態**：進行中

## 背景

花卉電商網站現有「模擬付款」功能（前端按鈕直接呼叫 API 更新訂單狀態），需升級為真實的綠界 ECPay 信用卡金流，讓用戶可透過綠界完成線上刷卡付款。

## 決策

| 項目 | 決策 |
|------|------|
| 模擬付款按鈕 | 完全移除，替換為「信用卡付款」按鈕 |
| 付款方式 | 僅信用卡（ChoosePayment: Credit） |
| 本地開發 Callback | 使用 ngrok 取得公開 URL |

## 付款流程

```
用戶點「信用卡付款」
  → POST /api/orders/:id/ecpay-checkout（需 JWT）
  → 後端產生 ECPay 表單參數 + CheckMacValue
  → 前端動態建立 <form> 並 submit 到 ECPay

用戶在 ECPay 頁面完成付款
  → [通道 A] ECPay POST /api/ecpay/notify（server-to-server）
      驗證 CheckMacValue → 更新訂單 status（paid/failed）
  → [通道 B] ECPay redirect /orders/:id?payment=success（瀏覽器跳轉）
```

## 新增檔案

### `src/utils/ecpay.js`
- `generateParams(order, merchantTradeNo, returnURL, orderResultURL, clientBackURL)` — 生成 ECPay 表單參數
- `verifyCheckMac(body, hashKey, hashIV)` — 驗證 ECPay 回呼簽章
- CheckMacValue 算法：參數字母排序 → URL encode（.NET 規則）→ 小寫 → SHA256 → 大寫
- 不需安裝新 npm 套件（使用 Node.js 內建 `crypto`）

### `src/routes/ecpayRoutes.js`
- `POST /notify`（掛載於 `/api/ecpay`，公開無認證）
- 驗證 CheckMacValue，失敗回 `0|Error`
- 查訂單：`SELECT * FROM orders WHERE REPLACE(order_no, '-', '') = ?`
- RtnCode=1 → status='paid'，否則 status='failed'，同時儲存 ecpay_trade_no
- 冪等保護：非 pending 訂單直接回 `1|OK`
- 回應純文字 `1|OK`（不是 JSON）

## 開發踩雷紀錄

實際串接時遇到三個問題，依序修正如下：

### 1. ECPay AIO Checkout API 路徑錯誤（HTTP 500）

**症狀**：點擊「信用卡付款」後，瀏覽器 console 出現
`POST https://payment-stage.ecpay.com.tw/Checkout/AioCheckout 500 (Internal Server Error)`

**原因**：使用了過時或錯誤的路徑 `/Checkout/AioCheckout`，與當前 ECPay 文件不符。

**修正**：對照 [官方文件](https://developers.ecpay.com.tw/2866/) 改用正確路徑 `/Cashier/AioCheckOut/V5`

```js
// src/utils/ecpay.js
const actionUrl = env === 'production'
  ? 'https://payment.ecpay.com.tw/Cashier/AioCheckOut/V5'
  : 'https://payment-stage.ecpay.com.tw/Cashier/AioCheckOut/V5';
```

**教訓**：不要憑印象寫第三方 API 路徑，每次串接都要去查最新官方文件。

---

### 2. CheckMacValue 計算錯誤（訊息代碼 10200073）

**症狀**：路徑修正後跳轉到 ECPay 頁面，立即顯示「交易失敗，訊息代碼：10200073，CheckMacValue Error」

**原因**：URL Encode 規則寫反了。曾錯誤地將 `-` `_` `.` `!` `~` `*` `'` `(` `)` 額外編碼為 `%2D` 等，但官方文件明確規定這些字元 **不編碼**，僅將空格轉為 `+`。

**修正**：對照 [官方 CheckMacValue 計算文件](https://developers.ecpay.com.tw/?p=2902) 還原為正確規則：

```js
// src/utils/ecpay.js
function dotNetUrlEncode(str) {
  // 不編碼字元：- _ . ! * ( )（與 encodeURIComponent 預設一致）
  // 空格：轉為 +
  return encodeURIComponent(String(str)).replace(/%20/g, '+');
}
```

**教訓**：第三方加密規則必須對照官方文件逐字實作，不要憑印象或網路上來路不明的「ECPay SDK 版本」自由發揮。

---

### 3. OrderResultURL 跳轉 404（POST 未處理）

**症狀**：ECPay 付款成功後，瀏覽器顯示
`POST https://xxx.ngrok-free.dev/orders/{orderId}?payment=success 404 (Not Found)`

**原因**：ECPay 付款完成後是用 **POST** 方式跳轉到 OrderResultURL（不是 GET），但 `src/routes/pageRoutes.js` 中的 `/orders/:id` 只註冊了 GET handler。

**修正**：將渲染邏輯抽成函式，同時註冊 GET 與 POST：

```js
// src/routes/pageRoutes.js
function renderOrderDetail(req, res) {
  renderFront(res, 'order-detail', {
    title: '訂單詳情',
    pageScript: 'order-detail',
    orderId: req.params.id,
    paymentResult: req.query.payment || ''
  });
}

router.get('/orders/:id', renderOrderDetail);
// 綠界付款完成後會以 POST 方式跳轉至 OrderResultURL
router.post('/orders/:id', renderOrderDetail);
```

**教訓**：金流回呼的 HTTP method 必須查文件確認，不要假設一定是 GET。`OrderResultURL` 與 `ReturnURL` 都是 POST，前者帶用戶瀏覽器跳轉、後者為 server-to-server 通知。
